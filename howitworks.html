PaperbackWriter · how it works

A mystery fails when the reader guesses early. So we test for that.

PaperbackWriter writes fair-play mystery novels with AI agents. The prose is the easy part. The hard part is hiding the culprit, so the plan is designed to hide them and then tested by a reader who has never seen it: before the prose is written, and again after.

The route

Nine stages, three of them gates

Each stage writes files into the book's folder, so any agent or person can pick up where the last one stopped. The red-bordered stages are gates: the book doesn't move on until a fresh reader's numbers clear the bar.

  1. Intakeyou and the author
    A 17-row build brief: place, period, sleuth, length, and whether the author wants to read it cold.
  2. Series bibleplanning model
    Canon for every book: geography, cast, voice, a banned list for period books. No culprit.
  3. Book planstrongest reasoning model
    Eight files, each under 2,000 words: suspects, suspicion curve, clue map, resolution map, chapter skeletons, canon, self-audit.
  4. Plan readfresh agent
    Reads only a stripped chapter outline, in five batches, naming suspects with exact quotes.
  5. Draftcheaper drafting model
    Five chapters per agent, in order. Obeys canon and nine hiding rules.
  6. Blind readfresh agent
    The same staged read on the real chapters. Targets: overall 7, fair play 7, misdirection 6.
  7. One fix passdrafting model
    Exact orders from the read's findings. Then stop fixing.
  8. Proofreadfresh agent
    Hard errors only, each one an exact-string replacement.
  9. Final read + releasefresh agent, then the build
    The score has to describe the exact text that ships. Then EPUB, RTF and PDF.

The arrows only go back to the plan. If the plan read fails, the suspects get redesigned, not reworded. If the first blind read scores misdirection under 5, the book goes back to stage 2. Sentence edits have never hidden a culprit.

Stage 2

The plan is where the hiding happens

The planner writes the solution first, then designs how suspicion should move chapter by chapter, then places every clue so it has an innocent reading and a louder scene to hide in. The 2,000-word cap per file keeps each one small enough for a model to hold and check.

FileWhat it decides
01_solution_and_suspectsThe culprit, the method, a one-clock timeline, and six suspects. At least two innocents have motive, method and access on the page, and the culprit is never caught lying.
02a_curveThe suspicion curve a sharp reader should follow, per chapter. Culprit ≤ .20 in the first third, ≤ .30 in the middle, ≤ .35 at 70%.
02b_cluesEvery clue: chapter, the louder event it hides behind, its innocent reading, whom it seems to point at. At most one culprit clue per three chapters before two-thirds.

04–07_chaptersOne skeleton per chapter: when, where, what happens, which clue IDs appear, the sleuth's own decisions.

auditThe planner reads its own plan at 30, 50 and 70% the way a reader would. Its fixes override the other files.
Stages 3, 5 and 8

The blind read can't look ahead

The reader is a new agent with no memory of the project. Its folder only ever holds chapters up to the next checkpoint. Later chapters don't exist on disk, so it can't peek.

  1. stage copies chapters 1–7 into the reader's folder.
  2. The reader writes log_ch07.json: every suspect, a probability, and quotes as evidence.
  3. check-read verifies the probabilities sum to 1 and finds every quote by exact string search. One invented quote voids the log.
  4. Only then is the next batch released. Checkpoints fall at about 30%, 50% and 70%, the chapter before the reveal, and the end.

What the gate measures

The culprit's line has to stay low

This is a real final read of a 24-chapter historical mystery built this way. The line is the probability the reader gave the true culprit at each checkpoint. The reader didn't settle on the culprit until chapter 20, one chapter before the reveal.

culprit's probability (this read)gate limitshaded: before 70%, where the culprit must stay hidden

The gate on the plan read is mechanical. gate scores each checkpoint against an answer written down before the read, with hashes of the plan and digest, so nobody can move the answer after seeing the results. At the first two checkpoints the culprit must rank third or lower; at the third, their probability must be .35 or less. Fail any and the next batch is never released.

The code

Count in Python, judge with the model

A model can't reliably search a long document. In earlier versions, a model auditor reported "no contradictions" in a book with five. So every check here is mechanical: string search, hashes, counts. The models do only the judging: writing, suspecting, scoring.

outline.py

Turns the planner's chapter files into what a reader would see. It strips labels, clue IDs like (C3), decision marks and cross-references, and refuses if any planner mark survives. Then it cuts the outline into five batches that end at the checkpoints.

reader · digest

plan.py

Structural check of a plan, without printing a spoiler: files present, each under 2,000 words, every chapter covered exactly once, and each digest batch identical to the stripped outline, so the reader reads exactly what was planned.

check-plan

reads.py

Staged release that can't go backwards, log verification by exact quote, the culprit's rank and probability, and the plan-read gate with hash-locked answers.

stage · check-read · gate

proof.py

Applies fixes as {file, old, new}. A fix whose old text isn't found exactly once is skipped and reported, so a correction can't land in the wrong sentence.

proof

export.py

EPUB 3 and RTF from the standard library, plus a 6×9 PDF through fpdf2. *italics* carry through to every format, and a * * * line stays a scene break.

narrate.py

Optional audiobook: a chapter to WAV with Kokoro text-to-speech, running locally, with a JSON file of pronunciation fixes for names the phonemiser gets wrong.

Checkpoints for any length, from outline.py 
def checkpoints(n_chapters):
    """About 30%, 50% and 70%, the chapter before the reveal, and the end."""
    n = n_chapters
    return (round(n * 0.3), round(n * 0.5), round(n * 0.7), n - 3, n)
# 24 chapters -> (7, 12, 17, 21, 24)
Why the rules are the rules

Each rule comes from a book that failed without it

Prose passes can't fix a plan.

Five overnight repair passes moved one book from 4.5 to 5.5 and back to 4.5. The faults that mattered were decided before a word was drafted.

Patch passes make it worse.

Three rounds of fixes moved the culprit's probability .58 → .62 → .72. Each edit that hid one tell created another. Hence one fix pass, then stop.

Self-ratings run about three points high.

A model grading its own prose gave 7.7 where outside readers gave 4.5. In-house scores are for comparing drafts, never for shipping.

A caught lie gives the culprit away.

In every read, the strongest tell was the culprit caught in a lie. Red herrings lie; the culprit never does before the reveal.

The quiet custodian gets caught.

Seven plan reads failed the same way: the reader ranked the quiet person tied to one key object first or second. Rewording didn't help; a different structure did.

An outline read is cheap.

About 130,000 reader tokens for five checkpoints, and it catches a visible culprit before a single chapter is written. It's harsher than the book, because an outline shows every detail at the same size.

cd PaperbackWriter

paperbackwriter reader   series/my-series/book1/plan
paperbackwriter digest   series/my-series/book1/plan/reader
paperbackwriter check-plan series/my-series/book1/plan
paperbackwriter gate     book1/plan/reference.json book1/plan/gate.json 7
